# RS 机械臂重力补偿与夹爪助力示例

`gravity_gripper_assist.py` 面向装有夹爪的 RS 机械臂：使用 `example/9` 的重力前馈方法驱动六个关节，手动拨动夹爪时提供辅助力矩，并将关节和夹爪位置发送到本机 Isaac Sim 接收端。夹爪助力的速度阈值、力矩和限位处理参考 [ReBot_Arm_DigitalTwin_RS](https://github.com/Yang-Ci/ReBot_Arm_DigitalTwin_RS)。

这是实验性真机示例，不是安全认证的控制器。使用前应固定并支撑机械臂，确认工作区域安全且急停可用。程序无法检测碰撞或自动保证关节、线缆和负载安全。动力学模型使用仓库 URDF，夹爪手指按零位计算，不包含额外负载；模型误差可能导致漂移。停止或通信异常时程序会请求电机失能，机械臂及夹爪可能失去支撑，夹持的物体也可能掉落。

本机受控测试采用数字孪生仓库的模型重力前馈缩放：J2 ×0.92，J3 ×0.98；其他关节 ×1.0。日志中的前馈为模型命令值，并非实测电机力矩。该调整能否改善下垂尚待验证。

**已知问题：** 实机体验时观察到 J2 持续漂移、末端下垂，原因尚未确认。使用时应保持支撑并观察；一次受支撑测试没有发现明显持续下垂，但尚未确认根因。

动力学计算读取 SDK 配置指定的 `urdf/RS/urdf/ReBot_Arm_RS.urdf`。默认仿真使用从同版 URDF 生成的 `usd/ReBot_Arm_RS/ReBot_Arm_RS.usda`；接收端保留旧 UDP 符号约定并转换到新版 USD 关节方向。设置 `REBOT_ISAAC_USE_LEGACY_USD=1` 可回退旧资产。两份 URDF 在本次更新时哈希一致。

## 模型预检查

在仓库根目录完成 `uv sync` 并将硬件配置切换到 RS，然后运行：

```bash
cd reBotArm_Isaacsim
python set_hw_rs.py
uv run python gravity_gripper_assist.py --check
```

`--check` 只检查配置和动力学模型，不连接 CAN、不发送电机命令。

## 真机运行

先确认 `can0` 正常、Isaac Sim 接收端已经启动、没有其他程序同时读写机械臂 CAN。夹爪默认按数字孪生仓库的范围工作：闭合 0 rad，打开 5 rad。该默认范围要求夹爪已按相同约定校零；本示例不执行校零。启动前会检查实际反馈是否在范围附近，若不满足请先检查校零或使用对应的实测范围，切勿强行启用。

**普通命令会直接控制真机。** 实机曾观察到 J2 下垂，原因尚未确认；运行时请保持支撑并观察。启动命令：

```bash
uv run python gravity_gripper_assist.py
```

需要适配不同校准时，也可通过 `--closed-rad` 和 `--open-rad` 指定端点，单位为弧度。

启动时，程序读取实际位置并逐步从当前位置保持过渡到低刚度补偿。夹爪默认进入手动助力模式；它不保证夹紧物体。终端可输入：

- `home`：请求回零；先等待机械臂连续静止 0.6 秒，再平稳回到六关节零位，到位后结束并请求失能；夹爪维持当前模式直到退出。
- `cancel`：取消等待中的回零请求，继续重力补偿。
- `assist`：恢复手动助力。
- `open` / `close`：缓慢向已校准的打开 / 闭合位置移动。
- `hold`：保持发送命令时的夹爪位置。
- `quit` 或第一次 `Ctrl+C`：先平稳回零，到位后停止并请求失能。回零正在进行时再次按 `Ctrl+C` 中止回零并请求失能。若请求被拒绝或回零中止，稍后再次按 `Ctrl+C` 会重新尝试回零。

回零先用 0.8 秒将增益平滑提高到 SDK RS 配置中每个关节的 MIT 保持增益，然后使用 SDK 的最小 jerk 多项式和固定时长轨迹；运动目标为约 4 秒，轨迹时长也受 30°/s 速度上限及加速度和 jerk 限制，较大行程会超过 4 秒。该版本不再根据跟随误差自动放慢轨迹。回零期间缩短了反馈轮询间隔，普通重补的轮询间隔不变。轨迹沿各关节直线插值，不能自动检测碰撞；使用前必须检查完整运动路径。回零时根据最新反馈锁定机械臂起始位置，并保留重力前馈；在同一个 MIT 控制循环内平滑过渡增益，不切换电机模式。夹爪保持已有的助力或控制模式。收到回零请求时先等待关节速度低于 2°/s 并连续稳定 0.6 秒，等待期间应远离机械臂运动范围；15 秒仍未稳定则取消本次请求，不会自动失能。控制循环延迟过长、跟踪误差超过 3°或无法在规定时间内稳定到位时，停止回零并在最近反馈姿态保持（电机仍使能），不会返回手动柔顺模式或强制发送零位目标；此时请勿推动机械臂，排查后可重试。所有关节的反馈与零位相差不超过 0.75°、保持 0.5 秒后才视为到位并请求失能。实时反馈故障仍会终止程序并请求失能。第一次 `Ctrl+C` 请求回零；回零正在进行时再次按 `Ctrl+C` 请求停止并失能。请求被拒绝或回零中止后，保持静止并排查原因，再次按 `Ctrl+C` 会重新尝试回零；`SIGTERM` 和终端挂断也直接停止，不自动运动。

手动移动夹爪轻微越过校准端点时，夹爪助力和位置控制暂停，手臂重力补偿继续；回到范围内后恢复。实时反馈超时、无法读取或控制线程出错时程序会停止并请求失能，不应依赖该机制替代急停。程序只能识别部分常见的冲突进程，并不能保证 CAN 总线完全独占。

夹爪反馈按校准的闭合到打开区间线性映射到仿真每指 0–45 mm；实际机械行程和仿真模型需要单独校验。示例曾进行手动示教和仿真同步测试；不同机械臂的方向、零点、惯量和夹爪行程需要分别验证。

## 离线检查

在仓库根目录执行：

```bash
uv run python -m unittest discover -s tests -p 'test_gravity_gripper_assist.py'
```

这些测试使用模拟电机，不接入 CAN，也不能替代真实设备的安全验证。固定轨迹版本已完成真机回零；现场观察到 J2/J3 在运动中有抖动，原因仍待进一步确认，电机跟不上时可能触发跟踪保护并中止回零。SDK 关节保持增益高于先前 kp=20 的测试版本，可能产生更大的保持力，请做好急停和可靠支撑。
