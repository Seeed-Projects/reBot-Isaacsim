# RS 机械臂重力补偿与夹爪助力示例

`gravity_gripper_assist.py` 面向装有夹爪的 RS 机械臂：使用 `example/9` 的重力前馈方法驱动六个关节，手动拨动夹爪时提供辅助力矩，并将关节和夹爪位置发送到本机 Isaac Sim 接收端。夹爪助力的速度阈值、力矩和限位处理参考 [ReBot_Arm_DigitalTwin_RS](https://github.com/Yang-Ci/ReBot_Arm_DigitalTwin_RS)。

这是实验性真机示例，不是安全认证的控制器。使用前应固定并支撑机械臂，确认工作区域安全且急停可用。程序无法检测碰撞或自动保证关节、线缆和负载安全。动力学模型使用仓库 URDF，夹爪手指按零位计算，不包含额外负载；模型误差可能导致漂移。停止或通信异常时程序会请求电机失能，机械臂及夹爪可能失去支撑，夹持的物体也可能掉落。

本机受控测试采用数字孪生仓库的模型重力前馈缩放：J2 ×0.92，J3 ×0.98；其他关节 ×1.0。日志中的前馈为模型命令值，并非实测电机力矩。该调整能否改善下垂尚待验证。

**已知问题：** 实机体验时观察到 J2 持续漂移、末端下垂，原因尚未确认。在定位并验证原因前，不应运行本示例控制真实机械臂。

## 模型预检查

在仓库根目录完成 `uv sync` 并将硬件配置切换到 RS，然后运行：

```bash
cd reBotArm_Isaacsim
python set_hw_rs.py
uv run python gravity_gripper_assist.py
```

不带 `--live` 只检查配置和动力学模型，不连接 CAN、不发送电机命令。

## 真机运行

先确认 `can0` 正常、Isaac Sim 接收端已经启动、没有其他程序同时读写机械臂 CAN。参照设备的实际电机反馈，分别测量夹爪完全闭合和打开时的电机位置，单位为**弧度**；不要将另一台设备的零点直接当作本机校准值，也不要用本示例设置零点。

示例使用环境变量传入本机实测端点，两个值均需先由操作者设置。`--live` 还要求 `--acknowledge-j2-drift`，明确确认实机曾观察到 J2 下垂且原因尚未解决。不要仅为绕过检查而添加该选项；应先完成诊断与受控验证：

```bash
uv run python gravity_gripper_assist.py --live \
  --acknowledge-j2-drift \
  --closed-rad "$GRIPPER_CLOSED_RAD" --open-rad "$GRIPPER_OPEN_RAD"
```

启动时，程序读取实际位置并逐步从当前位置保持过渡到低刚度补偿。夹爪默认进入手动助力模式；它不保证夹紧物体。终端可输入：

- `assist`：恢复手动助力。
- `open` / `close`：缓慢向已校准的打开 / 闭合位置移动。
- `hold`：保持发送命令时的夹爪位置。
- `quit` 或 `Ctrl+C`：停止并请求失能，不自动回零。

手动移动夹爪轻微越过校准端点时，夹爪助力和位置控制暂停，手臂重力补偿继续；回到范围内后恢复。实时反馈超时、无法读取或控制线程出错时程序会停止并请求失能，不应依赖该机制替代急停。程序只能识别部分常见的冲突进程，并不能保证 CAN 总线完全独占。

夹爪反馈按校准的闭合到打开区间线性映射到仿真每指 0–45 mm；实际机械行程和仿真模型需要单独校验。示例曾进行手动示教和仿真同步测试；不同机械臂的方向、零点、惯量和夹爪行程需要分别验证。

## 离线检查

在仓库根目录执行：

```bash
uv run python -m unittest discover -s tests -p 'test_gravity_gripper_assist.py'
```

这些测试使用模拟电机，不接入 CAN，也不能替代真实设备的安全验证。
